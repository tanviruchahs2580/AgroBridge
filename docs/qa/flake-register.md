# E2E flake register

Failures that are not reproducible on a re-run, with the evidence and the
action taken. Locally the suite runs with `retries: 0` deliberately (a retry
that hides a flake also hides the diagnosis), and CI allows 2 retries so a
genuine regression is not masked by an unrelated infrastructure blip — a
retried-but-passing test is reported as *flaky* by Playwright, and this register
is where those are accounted for instead of being quietly re-run away
(`apps/web/playwright.config.ts`).

Rules for this register: an entry needs a run log, a re-run result, and either a
root cause or a named next diagnostic step. A failure without a re-run result is
not a flake — it is an open defect.
| 2026-10-19 (third entry) | `a11y.spec.ts` authenticated `/market` scan | CI failed once with a color-contrast violation on a product-card button, then passed on the next run (icon-only commit in between; the re-run failed again on a different data mix). | `E-V2` CI logs: `.rounded-button` inside the 8th card; root-caused to `disabled:opacity-50` on the shared Button | **Root cause found, not a flake:** the disabled treatment blended white-on-green to 2.1–2.4:1, so every out-of-stock "Add to cart" card violated AA; whether an out-of-stock card appears in the scanned viewport varies by seed/list data.
