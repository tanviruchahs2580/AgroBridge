# Runbook — Support Error Codes (AB-XXXXX)

Every error envelope returned by the API carries a stable business `code`
(e.g., `AUTH_INVALID_CREDENTIALS`) plus an `AB-XXXXX` reference generated by the backend
error handler. Users may quote the reference when contacting support.

Error envelope shape:

```json
{ "error": { "code": "PAYMENT_DUPLICATE", "message": "...", "reference": "AB-38F2Q" } }
```

## Support lookup procedure

1. Get the `AB-XXXXX` reference (and time) from the user.
2. SSH to the VM and grep the API logs by reference first, then by requestId:

```bash
docker compose -f docker-compose.prod.yml logs --since 48h api | grep -F "AB-38F2Q"
# fall back to requestId if the envelope was truncated:
docker compose -f docker-compose.prod.yml logs --since 48h api | grep -F "<requestId>"
```

3. Each error log line contains `requestId`, `reference`, route and redacted context.
   Correlate the `requestId` across the request's full lifecycle lines.
4. If nothing matches: check log retention window and whether the incident predates the
   current container (`docker compose ps` start time).

Never ask users for passwords/OTPs during triage; the reference alone identifies the event.

## Stable business codes

| Code | Meaning | Farmer-facing message guidance (bn) |
|---|---|---|
| `AUTH_INVALID_CREDENTIALS` | Wrong phone/password or bad token | "ফোন নম্বর বা পাসওয়ার্ড ভুল। আবার চেষ্টা করুন বা পাসওয়ার্ড রিসেট করুন।" |
| `VALIDATION_ERROR` | Input failed schema validation | "কিছু তথ্য ঠিক নেই — লাল চিহ্নিত ঘরগুলো দেখে আবার লিখুন।" (show field errors verbatim) |
| `PHONE_NOT_VERIFIED` | OTP verification pending/incomplete | "আপনার ফোন এখনো যাচাই হয়নি। OTP দিয়ে যাচাই করুন।" |
| `PAYMENT_DUPLICATE` | Same payment intent already processed (idempotency guard) | "এই পেমেন্ট ইতোমধ্যে গৃহীত হয়েছে — ডাবল কাটা হয়নি। অর্ডার হিস্ট্রি দেখুন।" |
| `STOCK_INSUFFICIENT` | Requested qty exceeds available stock | "যতটা চেয়েছেন তত স্টক নেই। অপশন দেখুন বা পরে আবার চেষ্টা করুন।" |
| `AI_BUDGET_EXCEEDED` | Monthly AI spend budget exhausted; offline KB engine serves instead | "উপদেশ সেবা আজ ব্যস্ত। অফলাইন উত্তর দেওয়া হচ্ছে — কাল আবার চেষ্টা করুন।" |
| `FORBIDDEN` | Authenticated but not allowed (role/ownership) | "এই কাজটি করার অনুমতি আপনার নেই।" (never reveal which resource exists) |
| `NETWORK_TIMEOUT` | Upstream (payment/AI/SMS) timeout | "সংযোগে দেরি হচ্ছে। কিছুক্ষণ পর আবার চেষ্টা করুন। টাকা কাটা হলে অর্ডারে দেখা যাবে।" |

Guidance rules:

- Codes are **stable contract** — do not renumber/rename; frontend maps them to localized copy.
- Messages above are suggestions; keep them actionable, never blame the user.
- For `PAYMENT_DUPLICATE` and any money-related code, verify the order state in admin before
  promising anything.
